01 / Service ownership

Every service needs a named defender.

If nobody owns a service, nobody is accountable for its working state or its suspicious changes.

02 / Baseline

Know normal before hardening.

One of the easiest ways to break a system is to harden blindly.

01Running services
02Existing users
03Exposed ports
04Normal behavior

03 / Persistence review

Look beyond obvious malware.

Scheduled tasks
Services
Startup locations
Unauthorized users
SSH keys
Web shells
Odd cron jobs

Persistence detection becomes useful when it is a repeatable habit, not a one-time reaction to an obvious artifact.

04 / Communication loop

Shared context prevents duplicated work.

05 / Takeaway

The best defenders are not just fast with commands; they are organized under stress.

CCDC practice connected system administration, incident response, documentation, and teamwork.
